TASK 3 — END OF CREW → MOSAIC GLITCH → START
===============================================================

After the user reaches the end of the complete CREW experience,
introduce a new cinematic transition back to the beginning.

The desired visual language:

FINAL CREW STATE
↓
slight additional scroll
↓
world begins to fragment
↓
mosaic/glitch transition
↓
image/world breaks into controlled visual tiles
↓
tiles dissolve/rearrange/fragment
↓
the existing opening atmosphere emerges
↓
START

The transition should feel like the entire digital world is
being deconstructed and reconstructed.

It should be:

- smooth
- cinematic
- mysterious
- controlled
- premium
- atmospheric

NOT:

- a cheap glitch effect
- a sudden screen filter
- a hard cut
- a loading animation
- a random RGB glitch
- a generic TV-error effect

---------------------------------------------------------------

IMPORTANT: SCROLL-DRIVEN

The mosaic/glitch transition MUST be driven by the authoritative
scroll/progress state.

Do NOT use:

- setTimeout
- arbitrary delays
- animation that plays independently of scroll
- automatic timers
- teleportation
- hard progress jumps

The user should control the transition with scrolling.

For example:

final Crew state
→ 0%
→ 25%
→ 50%
→ 75%
→ 100%
→ opening state

The exact implementation is up to the existing architecture.

---------------------------------------------------------------

VISUAL CONCEPT

Explore a sophisticated mosaic treatment.

Possible visual behavior:

- scene breaks into rectangular/square tiles
- tiles subtly offset
- depth layers separate
- tiles distort
- image fragments reorganize
- fragments become atmospheric particles
- fragments dissolve into fog
- underlying opening scene begins to appear

The effect should feel like:

DIGITAL WORLD
→ DECONSTRUCTION
→ FRAGMENTATION
→ ATMOSPHERE
→ RECONSTRUCTION

Avoid excessive chromatic aberration.

Avoid aggressive RGB splitting.

Avoid generic "glitch transition" presets.

The effect should remain consistent with the cinematic visual
language of the website.

---------------------------------------------------------------

START STATE REVEAL

The final stage of the mosaic transition should naturally reveal
the existing opening state.

Do NOT create a second version of the Intro.

Do NOT reload the page.

Do NOT teleport the camera.

Do NOT reset the application abruptly.

Reuse the existing Intro start state.

The user should feel as though the world has transformed back
into its beginning.

---------------------------------------------------------------

CAMERA CONTINUITY

The camera must remain continuous throughout:

FINAL CREW
→ MOSAIC
→ ATMOSPHERE
→ START

No:

- position snap
- rotation snap
- FOV jump
- velocity discontinuity
- sudden lighting jump
- abrupt opacity change
- progress discontinuity

If the visual transition requires hiding the camera movement,
the transition itself must provide that visual occlusion naturally.

Do not use a second camera system.

---------------------------------------------------------------

AUDIO

The mosaic transition should have an appropriate sound design
layer if the existing audio architecture supports it.

It should feel:

- digital
- spatial
- mysterious
- cinematic

Avoid generic loud glitch sounds.

The sound should be subtle enough that it does not compete with
the background music.

Audio must also be reversible/cleanly managed when the user
scrolls backward.

No stale transition sound should remain playing after leaving
the transition.

---------------------------------------------------------------

REVERSE BEHAVIOR

This is critical.

The transition must work in BOTH directions.

Forward:

FINAL CREW
→ MOSAIC
→ START

Reverse:

START
→ MOSAIC
→ FINAL CREW

The visual state must interpolate deterministically from the
same authoritative progress.

Do NOT implement separate forward and reverse animations that
can drift apart.

Do NOT use a one-shot animation.

The same progress parameter should determine the transition state.

---------------------------------------------------------------

PERFORMANCE

Do not create an expensive full-screen effect that destroys
mobile performance.

Prefer:

- shader-based mosaic where appropriate
- controlled render resolution
- reusable buffers
- existing post-processing architecture
- limited tile counts
- adaptive quality

Avoid creating hundreds/thousands of independent React or
Three.js objects unnecessarily.

The transition must work on mobile as well.

Use existing quality tiers where appropriate.

---------------------------------------------------------------
