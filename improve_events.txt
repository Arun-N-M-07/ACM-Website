============================================================
2. CURRENT PROBLEM
============================================================

The current Events experience has several related problems:

1. The scroll does not feel fully controlled by the user's actual
   scroll input.

2. There is excessive empty space before the editorial content begins.

3. The 3D → 2D transition currently feels too much like one experience
   ending and another beginning.

4. The event title does not begin early enough when the black editorial
   canvas enters.

5. The editorial content feels more vertically spaced than necessary.

6. The right-side event rail is visually prominent relative to its
   actual usefulness.

7. The editorial typography and placement need to be refined using the
   supplied Basement screenshots as the visual reference.

These should be treated as connected problems rather than unrelated
CSS tweaks.

============================================================
3. TASK — FIX THE SCROLL CONTROL
============================================================

The user's physical scroll must be the PRIMARY DRIVER of the Events
experience.

The user should feel:

"I scroll → the experience responds directly."

NOT:

"I scroll → an invisible animation system decides where I should be."

Audit the complete existing architecture:

- Lenis
- global scroll progress
- Events progress mapping
- room progress
- editorial progress
- camera progress
- ScrollTrigger, if present
- pinned sections
- sticky sections
- section heights
- wrapper heights
- min-height
- viewport-height sections
- spacer elements
- transition ranges
- camera/editorial handoff
- any independently calculated progress values

Find the ROOT CAUSE.

Do NOT solve this by randomly changing:

- CSS heights
- margins
- transforms
- scroll multipliers
- animation durations

Do NOT use:

- timers
- setTimeout
- setInterval
- fake scroll positions
- forced snapping
- automatic advancement

The user's scroll must directly control progression.

============================================================
4. SCROLL BEHAVIOR — REQUIRED
============================================================

If the user scrolls slowly:

the experience progresses slowly.

If the user scrolls normally:

the experience progresses naturally.

If the user scrolls quickly:

the experience progresses more quickly without breaking.

If the user stops:

the composition should stop.

If the user reverses:

the experience must reverse naturally.

There should be no feeling of the site fighting the user's input.

Avoid:

- excessive inertia
- invisible progress ranges
- giant dead travel
- artificial pin durations
- forced section jumps
- scroll hijacking
- automatic transitions
