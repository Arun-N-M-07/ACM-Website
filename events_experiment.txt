============================================================
THE CORE IDEA
============================================================

The new Events experience is:

                EVENTS ENTRY
                     ↓
            LARGE 3 × 3 ARCHIVE
                     ↓
          HOVER / FOCUS AN EVENT
                     ↓
      contextual action appears
                     ↓
          CLICK EVENT
                     ↓
       SMOOTH CAMERA TRANSITION
                     ↓
          SELECTED EVENT VIEW
                     ↓
           SCROLL THROUGH
          EVENT INFORMATION
                     ↓
       DESCRIPTION / DETAILS
                     ↓
      REGISTRATION IF AVAILABLE
                     ↓
                ESC / BACK
                     ↓
          RETURN TO FULL SHELF
                     ↓
        USER CAN CHOOSE ANOTHER
                     ↓
             OR CONTINUE SCROLL
                     ↓
       ALL EVENTS' INFORMATION
        IS PRESENTED SEQUENTIALLY
                     ↓
          FINAL EVENT CONTENT
                     ↓
          SHELF APPEARS AGAIN
                     ↓
             CONTINUE SCROLL
                     ↓
          SHELF SPLITS IN HALF
                     ↓
               PORTAL
                     ↓
             THE CREW


This is the new Events information architecture.


============================================================
1. NO MORE FORCED EVENT ROOM TOUR
============================================================

The existing concept of physically touring individual
event rooms should no longer be the default Events experience.

The user should NOT have to:

enter Event 01 room
→ walk through it
→ Event 02 room
→ walk through it
→ Event 03 room
→ etc.

Instead, Events becomes an ARCHIVE.

The user first encounters one large physical archive.

The archive contains all Events.

The user chooses what they want to inspect.


============================================================
2. THE LARGE 3 × 3 ARCHIVE
============================================================

After entering the Events environment, the user should see
a large, monumental 3 × 3 event archive.

3 columns.

3 rows.

9 event positions.

The archive should feel like a physical installation.

It should NOT feel like:

- HTML cards
- a CSS grid
- a dashboard
- a website gallery
- nine floating rectangles
- a generic bookshelf
- nine unrelated 3D boxes

It should feel like a real architectural object.

Think:

museum archive
exhibition wall
institutional showcase
architectural display
physical event archive
curated collection


============================================================
3. THE ARCHIVE ENVIRONMENT
============================================================

The shelf must NOT float in empty space.

Create a convincing architectural environment around it.

Possible elements:

- structural side walls
- vertical columns
- recessed compartments
- floor
- ceiling
- framing
- practical lights
- shadows
- depth
- atmospheric haze
- architectural materials
- subtle reflections
- controlled highlights

The exact architecture should be consistent with the existing
ACM-CEG Events environment.

Do not create a completely unrelated visual world.


============================================================
4. LARGE EVENTS TITLE
============================================================

A large 3D / environmental:

EVENTS

title should be integrated above or around the archive.

It should feel like part of the physical installation.

It should NOT look like:

<h1>EVENTS</h1>

placed over a WebGL object.

Use the existing ACM-CEG typography language.


============================================================
5. EVENT POSITIONS
============================================================

Each of the 9 positions corresponds to a real event from the
existing event dataset.

Do not invent events.

Do not invent event information.

Do not fabricate:

- titles
- descriptions
- dates
- registration URLs
- organizers
- prizes
- statistics
- winners
- categories.


============================================================
6. THE INITIAL SHELF IS AN INTERACTIVE INDEX
============================================================

The initial shelf is NOT merely decorative.

It is the primary Events navigation surface.

The user should be able to inspect the events directly.

When the pointer moves over an event:

the event becomes visually selected.

The selected event should feel like a physical object being
focused.


============================================================
7. HOVER BEHAVIOUR — BASEMENT INTERACTION REFERENCE
============================================================

This is one of the most important parts of this document.

Study the actual Basement website interaction.

When an item is hovered/focused there is a clear contextual
response.

ACM-CEG should implement the equivalent interaction.

For example, conceptually:

          EVENT OBJECT

             ↓ hover

     selected / emphasized

             ↓

      contextual action

        "VISIT CODHER"

or:

        "EXPLORE CODHER"

or:

        "VISIT [EVENT NAME]"


The exact wording can be determined from the ACM-CEG
event name and design language.

The important part is:

The user should immediately understand:

"I am currently focusing this event."

The contextual action should belong visually to that event.


============================================================
8. HOVER VISUAL RESPONSE
============================================================

The selected event can respond through:

- subtle depth movement
- local illumination
- material response
- contrast
- scale
- edge highlight
- contextual typography
- surrounding event dimming

Do NOT make this a generic CSS hover effect.

It should feel like a physical archive object reacting.


============================================================
9. ONLY ONE EVENT SHOULD FEEL SELECTED
============================================================

When Event A is hovered:

Event A = dominant.

Other events = secondary.

Do not make all nine objects equally bright.

The selected item should establish hierarchy.


============================================================
10. CONTEXTUAL ACTION
============================================================

The selected event should reveal an action similar in spirit
to the Basement interaction.

For example:

[ VISIT CODHER ]

or:

[ EXPLORE CODHER ]

or:

[ VIEW EVENT ]

Use the actual event name.

The action should be aesthetically integrated.

Do NOT make a giant generic rounded CTA.

Do NOT make it look like a SaaS dashboard.


============================================================
11. CLICKING AN EVENT
============================================================

When the user clicks the selected event:

DO NOT instantly teleport.

The camera should transition VERY SMOOTHLY toward that
specific event.

This is one of the highest-priority requirements.

The camera movement should feel:

- cinematic
- physical
- deliberate
- extremely smooth
- spatially coherent
- premium

The selected event should become the destination.

The movement should feel like:

"I'm approaching this particular archive item."

NOT:

"The webpage switched sections."


============================================================
12. CAMERA TRANSITION
============================================================

The camera should:

1. recognize the selected event
2. begin moving toward it
3. maintain smooth interpolation
4. preserve orientation continuity
5. preserve appropriate FOV
6. approach the selected event naturally
7. settle into a dedicated event viewing composition

No:

- teleport
- hard cut
- snap
- sudden FOV jump
- second camera
- arbitrary timeout
- fake loading state


============================================================
13. EVENT DETAIL VIEW
============================================================

Once the camera has arrived at the selected event:

the user should see the event as the primary subject.

The event should have a dedicated visual composition.

This is where the experience transitions from:

3D ARCHIVE

into:

EVENT INFORMATION EXPERIENCE.


============================================================
14. THE 2D EVENT INFORMATION UI
============================================================

THIS IS THE MOST IMPORTANT REFERENCE REQUIREMENT.

The detailed event information presentation should closely
follow the Basement website's showcase/project presentation
model.

Again:

Actually EXPERIENCE the reference website before implementing.

Do not invent an unrelated editorial layout.

Observe:

- how the selected item becomes the main focus
- how the title is presented
- where metadata appears
- how description content is positioned
- how spacing is handled
- how content enters
- how the user scrolls through it
- how secondary information is presented
- how actions/links are presented
- how the page maintains visual identity
- how the experience feels like a showcase rather than a
  conventional webpage.


============================================================
15. EVENT DETAIL STRUCTURE
============================================================

For each event, the detailed view should conceptually contain:

EVENT TITLE

EVENT METADATA

DATE
CATEGORY
OTHER EXISTING INFORMATION

LARGE EVENT DESCRIPTION

ADDITIONAL INFORMATION

REGISTRATION ACTION
ONLY IF A VALID REGISTRATION LINK EXISTS


The exact visual arrangement should be determined after
studying the Basement reference.

Do not turn this into a generic centered card.


============================================================
16. LARGE TYPOGRAPHY
============================================================

The event title should have strong visual presence.

Use large editorial typography.

The composition should have:

- scale
- negative space
- hierarchy
- controlled alignment
- deliberate spacing

Do not cram everything into a small panel.


============================================================
17. EVENT DESCRIPTION
============================================================

The event explanation should be genuinely readable.

The user should be able to understand:

What is this event?

What does it involve?

What is the purpose?

What information does ACM-CEG currently provide about it?

Use the actual existing description.

Do not fabricate missing content.


============================================================
18. REGISTRATION
============================================================

If an event has a real registration link:

show it.

For example:

REGISTER

or the appropriate ACM-CEG wording.

The registration action should visually belong to the event
presentation.

If no registration link exists:

DO NOT show a fake registration button.

Simply present the event information that exists.


============================================================
19. SCROLL INSIDE THE EVENT
============================================================

After clicking an event and arriving at its dedicated view:

scrolling should reveal the event's information.

The experience should not immediately dump all text on screen.

Use the same general interaction philosophy as the Basement
reference:

large visual hierarchy
→ information
→ description
→ details
→ action.


============================================================
20. SCROLL SHOULD FEEL LIKE EXPLORING THE EVENT
============================================================

The scroll should not feel like:

"scrolling down a normal webpage."

It should feel like:

"I am exploring the selected event."


============================================================
21. ESCAPE / BACK TO SHELF
============================================================

This is CRITICAL.

After entering an event:

the user should be able to press:

ESC

and return to the full 3 × 3 shelf view.

The return must be smooth.

Do NOT reload.

Do NOT recreate the entire Events scene.

Do NOT teleport.

Do NOT reset the website.

The camera should smoothly return to the archive composition.

The shelf should once again be visible as a whole.


============================================================
22. ESC RETURN BEHAVIOUR
============================================================

Conceptually:

FULL SHELF
    ↓
hover Event X
    ↓
click Event X
    ↓
camera smoothly approaches Event X
    ↓
Event X detail experience
    ↓
ESC
    ↓
camera smoothly returns
    ↓
FULL SHELF


The transition should feel like leaving an exhibit and
returning to the exhibition hall.


============================================================
23. IMPORTANT: ESC MUST NOT BREAK SCROLL STATE
============================================================

If the user presses ESC:

the selected event state should be cleared correctly.

No stale selected event.

No stale contextual overlay.

No stale camera target.

No stale animation.

No stale audio.

The shelf should return to a clean interactive state.


============================================================
24. MULTIPLE EVENT EXPLORATION
============================================================

The user should be able to:

open Event A
→ ESC
→ open Event B
→ ESC
→ open Event C

without the system degrading.

Each event should use the same architecture.

No duplicated scene systems.


============================================================
25. THE OTHER IMPORTANT PATH
============================================================

The user may never click an event.

They may simply scroll.

In that case, the Events section should become a sequential
editorial archive.


============================================================
26. SCROLLING THROUGH ALL EVENTS
============================================================

When the user is in the overall Events experience and simply
scrolls without selecting a specific event:

the event information should appear ONE EVENT AT A TIME.

Conceptually:

SHELF

↓

EVENT 01 INFORMATION

↓

EVENT 02 INFORMATION

↓

EVENT 03 INFORMATION

↓

EVENT 04 INFORMATION

↓

EVENT 05 INFORMATION

↓

EVENT 06 INFORMATION

↓

EVENT 07 INFORMATION

↓

EVENT 08 INFORMATION

↓

EVENT 09 INFORMATION

↓

SHELF AGAIN

28. EVENT SECTIONS SHOULD FEEL LIKE SHOWCASE ENTRIES
============================================================

Each event should feel like its own showcase entry.

Not a card.

Not a blog article.

Not a university event announcement.

A showcase entry.


============================================================
29. EVENT MEDIA
============================================================

If the ACM-CEG repository already contains imagery/media for

The layout must still look complete through typography,

============================================================
30. EVENT ORDER
============================================================

Use the existing event ordering/data source.

Do not randomly reorder events.

The 3×3 shelf order and sequential editorial order should

If the repository already defines an event order, preserve it

============================================================
31. INITIAL SHELF → EDITORIAL EXPERIENCE
============================================================

The initial shelf remains visible first.

If the user simply scrolls:

the shelf transitions into the first event's editorial
presentation.

This should feel like entering the archive's content layer.


============================================================
32. INITIAL SHELF → SELECTED EVENT
============================================================

If the user instead hovers and clicks:

the selected event becomes the destination.

The camera approaches that event.

The event detail presentation appears.

The user can scroll through its information.

ESC returns to the shelf.

============================================================
34. THE VISIT THE CREW ACTION
============================================================

The initial shelf should also have:

VISIT THE CREW

This is independent from event selection.

If the user activates it:

the shelf physically splits.

It should NOT jump directly to Crew.


============================================================
35. SHELF SPLIT
============================================================

The shelf splits into two physical halves.

LEFT HALF
moves left.

RIGHT HALF
moves right.

CENTER
opens.

A portal / spatial passage becomes visible.

The effect must feel physical.

Not:

fade out
scale down
random glitch
dissolve.


============================================================
36. PORTAL
============================================================

The portal should feel like a hidden architectural passage.

It should belong to the ACM-CEG world.

Avoid generic:

- magic portal
- sci-fi ring
- neon portal
- gaming portal

It should feel like the archive itself was concealing
the next world.


============================================================
37. CAMERA TO PORTAL
============================================================

After the split:

continued scrolling moves the camera toward the portal.

Do not automatically teleport.

The camera journey remains scroll-driven.


============================================================
38. THE CREW
============================================================

After the portal:

continue into the EXISTING THE CREW experience.

Preserve:

- existing Crew entrance
- touch-and-hold
- domain experience
- member experience
- existing camera choreography
- existing visual identity.

the shelf must return.

"I have completed the event archive."
